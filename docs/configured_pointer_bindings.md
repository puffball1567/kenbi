# 順序付き検証でのポインタ再代入

`source-pointer-bindings.c.v1` は、ローカルのポインタ変数と値渡しポインタ引数への
単純な `p = q` / `p = buffer + 定数` を追跡する。
状態機械、外部アクセス容量/整列の順序付き解析で使用する。新しい注釈は不要。

代入はポインタ変数の参照先変更であり、参照先へのwriteアクセスとして扱わない。
起源・バイト位置・容量・保証配置を右辺から更新し、右辺のメモリアクセスも検査する。
読み取り専用属性、解放・寿命終了、非同期借用は変数名ではなく領域の起源に残る。
したがって、借用中のバッファを指していた変数を別のバッファへ切り替えても
元の借用は終了しない。別名から元のバッファにアクセスすれば競合を検出する。

ブロック終了では、そのブロックで導入した束縛だけを除去する。外側の変数に対する
代入を入口値に戻さない。ブロック内の自動変数を指す値が外へ残った場合、
その起源は寿命終了済みとして保持し、後続アクセスを `EXPIRED_BORROW_ORIGIN` で拒否する。
シャドーイングした変数はClangの識別子で区別する。
関数のポインタ引数は値渡しなので、仮引数への代入は呼び出し元の変数を変更しない。

分岐・ループごとに束縛を追跡し、固定点の比較にも含める。
容量/整列が不明な値へ代入した後は、以前の保証を残さない。
nullや未知パラメータも既知のバッファへ昇格させない。
範囲外へ出てから戻した計算の無効状態も維持する。

グローバルへの代入は `UNKNOWN_POINTER_BINDING`（未検証）。
volatile/atomic、呼び出し結果、間接的なポインタ変数変更、複合代入、一般のキャスト等は
この機能の対応範囲外であり、未対応構文や後続アクセスの情報不足として未検証になる。
ヒープ所有権や物理領域、一般のポインタ演算安全性の証明を追加するものではない。

回帰: `python3 tests/run_tests_pointer_bindings.py`。
独自作成の `tests/c/t261_pointer_bindings.c` と追加C/JSONを使用。
新規依存・外部コード・デバイス仕様の取り込みはない。

## 同じ宣言の寿命が繰り返される場合（2026-09-20）

ループの各周回で同じ宣言が実行されても、前の寿命から逃げた参照を再有効化しない。
寿命終了時、残存するポインタ束縛を恒久的な失効起源へ移し、新しい宣言の起源と区別する。
新しい領域のアドレスを明示的に代入し直した束縛だけが利用可能になる。

以前は固定点探索の宣言識別子を再利用した際に、古い別名まで有効に戻る検出漏れがあった。
修正前の実バイナリで誤ったverified判定を再現し、修正後はEXPIRED_BORROW_ORIGINに変わることを確認。
過去の寿命の数を無限に増やさず、失効起源をまとめることで固定点探索も維持する。
これはCの自動変数の寿命追跡であり、C++ placement newの参照更新規則を実装するものではない。

回帰: `python3 tests/run_tests_lifetime_reentry.py`。
while/do/for、別名・オフセット・continue、可視ヘルパー/別翻訳単位、APIアクセス、

## 独立したポインタ更新（2026-09-21）

ローカル変数・値引数のポインタに対する独立した前置/後置 `++` / `--` と
`+=` / `-=` を追跡する。要素の型サイズに応じたオフセットを既存の起源/容量へ適用し、
`pointerFormation` の検査後に束縛を更新する。能力識別子は `source-pointer-updates.c.v1`。
`for` の更新式にも適用する。更新結果を別の式で使う `*p++` 等は未対応。

`memoryAccess: true` では形成時点で範囲を検査し、末尾の次の位置は許可するが、
そこからのread/write、さらに先への移動、先頭より前への移動は違反とする。
いったん範囲外へ出てから戻す操作も許可しない。未知起源・動的増分は未検証で拒否する。
メモリアクセス検証を指定していない場合も束縛と容量を更新し、契約検査で利用する。
その場合、ポインタ形成自体の安全性の証明を結果に追加したとは扱わない。

更新前の別名や保持中の非同期借用は元の領域を参照し続ける。ポインタ変数自身の更新と、
借用対象バッファの変更を混同せず、更新後の参照先アクセスで借用競合を検査する。
volatile/atomic、間接ポインタ書き換え、マクロ更新、右辺の関数呼び出しは未対応。
