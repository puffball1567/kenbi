# ソース呼び出し深さの上限（実装済み）

`source-call-depth.c.v1` は、検査ルートから同時に入れ子となるソース上の関数呼び出し数を
保守的に計算し、profile の要求と照合する。

```json
{"profiles": {"bounded": {"maxCallDepth": 4}}}
```

ルートを1と数える。leaf は1、root → helper → leaf は3。
同じ leaf を順番に2回呼んでも、その深さを加算しない。
分岐・ループ中の呼び出しを含めたグラフの最大経路を取り、実行可能性の精密な解析や
最適化によるインライン化・末尾再帰除去は仮定しない。

値は1～1000000の整数。bool・小数・文字列・ゼロ・負数・範囲外を拒否する。
forbid/protocols/context と併用できるほか、maxCallDepth だけの profile も作れる。
extends で同名 profile を合成すると、小さい上限を採用する。子設定で要求を弱められない。

## 外部仕様と本体の適合

外部 functions 契約には、そのAPI自身を1として含む最大深さを明示する。

```json
{
  "symbol": "c:@F@external_api",
  "effects": [],
  "maxCallDepth": 2,
  "assumption": "api.depth.model"
}
```

root → external_api でこの契約を使うと上限は3。
外部 bound は、API内の入れ子や呼び戻しを含む深さについての外部前提であり、
Kenbi が実装を証明した事実ではない。受け入れても conditional として記録する。
既知のアロケータや effects: [] から深さ1と推定しない。
外部上限の欠落は MISSING_CALL_DEPTH_CONTRACT で未検証となる。

本体がある場合は宣言上限を解析の近道にせず、本体から計算する。
宣言より大きければ CONTRACT_CALL_DEPTH_MISMATCH。
未使用の上限契約付き関数でも、この適合検査は行う。
その証明が外部上限に依存する場合は、depthContractAssumptions に前提を記録し、
未受け入れなら全体の受け入れを拒否する。未使用だから前提を隠すことはない。

## 結果と未対応

- CALL_DEPTH_LIMIT: 計算したソース深さが profile の要求を超える。
- RECURSIVE_CALL_DEPTH: 再帰する本体の有限深さを確立できない。
- UNRESOLVED_CALL_DEPTH: 間接・未解決の呼び出し。
- UNSUPPORTED_CALL_DEPTH: 暗黙の呼び出し等の未対応構文。
- CALL_DEPTH_ANALYSIS_LIMIT: 解析側の探索制限（10000訪問または解析中の入れ子128）を超過。

解析不能な場合は要求値や自己申告値を計算結果に流用しない。
obligation の callDepth には requiredMaximum（要求）、upperBound（計算結果、不明ならnull）、
callChain（最大の既知経路）、assumptions（外部前提）、unit: source-call-frames を分けて出力する。
本体付き契約の適合結果は depthContractEvidence に declaredMaximum と upperBound を記録する。
深さ検査を要求しない obligation の callDepth は null。

再帰禁止との併用は可能だが、本機能は再帰深度の帰納的な証明ではない。
可視の再帰本体に上限を書くだけでは成立しない。
探索制限により、大きな非再帰グラフでも未検証となる場合がある。

ブロック指定では現在の囲む関数の呼び出しを1とし、ブロック内から始まる呼び出しの深さを調べる。
ブロックより前の呼び出しや、検査ルートに至る caller の段数はこの要求の範囲外。
アプリケーション全体に要求する場合は、その入口から検査する必要がある。

これは ABI 上の実スタックフレーム数・使用バイト数、割り込みの追加スタック、
ループ回数、終了性、処理量、WCET を証明するものではない。
これらは対象・ビルド・実行条件に対応した別モデルが必要。

テスト: `python3 tests/run_tests_depth.py`。
C フィクスチャと契約は独自作成。依存追加や外部資料の取り込みはない。


## 共有する呼び出し先の再利用（2026-09-19）

解析を完了し、すべての呼び出しについて上限を確立した部分グラフは、同じ検査内で再利用する。
複数の関数から同じヘルパーへ到達しても、その配下を繰り返し展開しない。
再帰探索中の項目、未解決の呼び出し、探索制限に達した項目は確立済みとして保存しない。

保存する深さは、その関数を入口とした相対的な値。再利用時には新しい caller の段数を加え、
最大経路と違反位置もその呼び出し元に対応させる。
外部上限へ依存した前提は同じ検査結果に残り、未受け入れなら拒否する。
検査をまたぐ永続キャッシュではなく、別ルート・別実行で前提を使い回すものではない。

これにより共有先が多い非再帰グラフでの不要な探索上限超過を減らした。
解析中の入れ子制限は解析器の作業量を制限するもので、計算できるソース深さの定義ではない。
その他の未対応項目や保証範囲は変わらない。
