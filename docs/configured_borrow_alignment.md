# 非同期借用バッファのアラインメント要求

2026-09-19。`source-borrow-alignment.c.v1` を実装。
protocol 操作の `borrow.alignment` は借用ポインタに要求する整列単位。
無条件・結果分岐付きの借用の両方に適用し、`minBytes` と併用または単独で指定できる。

```json
{"borrow": {"argument": 2, "mode": "read", "minBytes": 16, "alignment": 4}}
```

設定値は1〜536870912の2の冪。ゼロ・負数・非整数・その他の値は設定エラー（終了コード2）。
設定に書かれた値を実際の配置として仮定しない。省略時は整列要求を追加しない。

Clang の `clang_Type_getAlignOf` から、解析対象のコンパイル条件で型が保証する配置を取得する。
固定長の自動変数・配列、int値引数自身の記憶領域を対象とする。
借用起点とは別に、ストレージ先頭の保証アラインメントとバイト位置を維持し、
別名・可視関数引数・別翻訳単位へ引き継ぐ。ポインタの見かけの型だけでは保証を強めない。

先頭の保証が A、オフセットが O、要求が R の場合:

- A が R の倍数で O も R の倍数: 整列要求は検証済み。
- O が gcd(A, R) の倍数でない: 必ず不整列なので `BORROW_ALIGNMENT_REQUIREMENT`（違反）。
- その他: 追加の配置情報が必要なため `UNKNOWN_BORROW_ALIGNMENT`（未検証）。

例えば int の配置が4の対象で先頭を8に整列する要求は未検証。
実行時アドレスが偶然8に整列する可能性があるので、必ず違反とは言わない。
同じ起点から1バイトずれたポインタは4にも8にも整列しないことが分かる。
動的オフセットは位置不明として未検証。一度範囲外へ出たポインタは
整列要求だけを指定した場合も `BORROW_POINTER_RANGE` で拒否する。

各 obligation の `borrowAlignment` に要求・先頭の保証・位置・判定・仕様ファイル・
引数番号・ソース位置・呼び出し経路・結果分岐を記録する。
診断の `alignmentRequirement` にも同じ証拠を含める。単位は `c-sizeof-bytes`。
容量条件や既存の借用条件で先に停止した経路では整列証拠が空の場合がある。
デバイス動作や外部APIの契約前提は、配置の検証成功とは別に conditional として維持する。

整数リテラルを直接指定した `_Alignas` / GNU `aligned` にも対応する（下記参照）。
それ以外の未対応属性付き宣言は未検証を維持する。
ヒープ・配置先アドレス・DMA可能領域・MMIO・キャッシュ・atomicの保証ではない。
一般のCPUアクセスや minBytes/alignment が未指定のポインタ演算の検証でもない。

独自作成の `tests/c/t252_borrow_alignment.c` と `tests/run_tests_alignment.py` で検証する。
既存 libclang のAPIを使用し、新規依存・外部コードやデバイス仕様の取り込みはない。

## 明示的な配置指定（2026-09-19）

自動変数の `_Alignas(16)`、`__attribute__((aligned(16)))`、
`__attribute__((__aligned__(16)))` に対応した。
引数はCの整数リテラルの直接指定に限る（対応する表記は下記参照）。
Clang の構文・型検査が成功し、対応するカーソルが整列属性に分類されていることを確認した上で、
属性のソース位置にある指定値を照合する。単なるコメントや同名の識別子から保証を作らない。

複数指定は型の自然な配置と全指定値の最大を採用する。`_Alignas(0)` は自然な配置を弱めない。
指定が不正な C（2の冪でない、自然な配置より弱い等）は既存のコンパイル入力エラーで拒否する。
ポインタ変数自身への指定は、そのポインタが指すバッファの配置を強めない。

現在の libclang では整列属性の値を直接取得できず、C11属性のカーソル範囲は引数部分を
含まないため、属性位置から宣言内のトークンを読んで照合する。
マクロ展開の位置は通常のファイル位置と区別し、ソース中の見かけの引数を採用しない。
型名、式、値の省略、マクロ経由の指定は未検証を維持する。
他の属性（例: cleanup）が併用される場合も、その未対応理由を消さない。

新規依存や外部実装の取り込みはなく、既存 libclang の位置・属性・トークンAPIを使用する。
追加の回帰例は `tests/c/t253_explicit_alignment.c`、
実行テストは `tests/run_tests_alignas.py`。

## C整数リテラルの表記（2026-09-20）

直接指定の10進に加え、16進（0x/0X）、8進（先頭0）、標準の U/L/LL サフィックスに対応。
`_Alignas(020)` は十進16、`_Alignas(0x10UL)` も16として照合する。
ゼロ指定は自然な配置を維持する。複数指定は表記によらず最も強い指定を採用する。

Cの基数とサフィックスを厳密に判別し、桁を加える前に上限を確認して解析器の
整数オーバーフローを避ける。Clangの構文・型検査と属性/ソース位置の確認は維持する。
2進リテラルなどの拡張表記、一般の定数式、型指定、マクロの展開は今回追加していない。
未対応表記を先頭部分だけ読んで採用することはない。

追加テスト: `tests/c/t254_alignment_literals.c`、`tests/run_tests_alignment_literals.py`。
独自作成のコード・テストのみで、外部コード・仕様・依存の追加はない。
