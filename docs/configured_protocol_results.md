# 戻り値に応じた状態と借用（実装済み）

`--safety` の `source-protocol-results.c.v1` は、C の `int` 戻り値を
`zero` / `nonzero` に分け、状態・持続借用と対応付ける。
関数名に成功・失敗の意味を組み込まず、外付け仕様で両方の結果を定義する。
既存の `void` 操作の無条件 `to` は引き続き使える。

## 外付け仕様

既存の protocols パッケージ内の operation に次を指定できる。

```json
{
  "symbol": "c:@F@try_start",
  "argument": 1,
  "from": ["ready"],
  "outcomes": [
    {"result": "zero", "to": "busy", "borrow": {"argument": 2, "mode": "read"}},
    {"result": "nonzero", "to": "ready"}
  ]
}
```

完了操作は次のように、失敗した場合に借用を保持できる。

```json
{
  "symbol": "c:@F@try_finish",
  "argument": 1,
  "from": ["busy"],
  "outcomes": [
    {"result": "zero", "to": "ready", "releaseBorrow": true},
    {"result": "nonzero", "to": "busy"}
  ]
}
```

両カテゴリを一度ずつ指定することが必須。未知のカテゴリ、重複、欠落、未知キー、
存在しない状態、無条件の `to` / `borrow` / `releaseBorrow` との混在は入力エラー。
`from` と resource argument は共通。借用取得と解放の条件は各 outcome に属する。
`releaseBorrow` を省略した遷移は、状態が終端に変わっても借用を終了しない。
成功をゼロと決めつけず、nonzero 側に借用取得を指定することも可能。

外部効果・メモリアクセス契約も引き続き必要。`accesses` は両結果に共通の
呼び出し入口でのアクセス集合であり、結果別の副作用仕様ではない。
状態遷移や実機・外部実装の振る舞いは明示された外部前提。
受け入れた場合も検査結果は `conditional` で、`verified` には昇格しない。
利用可能な操作本体との契約適合検査は未実装なので未検証を残す。

## ソースの検証

```c
int rc = try_start(&transfer, buffer);
if (rc != 0) return;
if (try_finish(&transfer) != 0) abort_transfer(&transfer);
```

`abort_transfer` が借用終了を保証する外部契約なら、失敗経路も含めて借用を終えられる。
戻り値を無視した呼び出しは両経路を検査し、成功だけとは仮定しない。
完了の失敗経路でバッファを変更したり、復旧せず return したりすれば違反になる。

対応範囲:

- `int` ローカル変数への初期化・代入・コピー、ゼロとの `==` / `!=`、真偽判定、`!`。
- 呼び出しを含まない結果式の `&&` / `||`。評価されるメモリアクセスも検査する。
- `if (try_start(...))`、`if (0 == try_start(...))` など、単一呼び出しの結果判定。
- `while (try_finish(...))` の条件を各周回で再評価し、成功時だけ借用終了。
- 本体を解析できるヘルパーの `return`。別翻訳単位やローカル変数経由も追跡。
- 直接代入、別名を通じた変更、可視ヘルパーや外部 accesses 契約による変更で、古い結果の情報を無効化。
- write 借用の開始で、対象バッファに保存された結果情報を無効化。

これはゼロか否かの解析であり、異なる非ゼロのエラーコード同士が等しいとは判断しない。
`rc == 1` だけで全失敗を処理したとは認めない。
一般の整数計算・値域解析、int 以外のスカラー引数への結果情報伝播、ポインタ戻り値、
enum/unsigned/bool 戻り値を持つ操作、幅を狭めた結果の捕捉は対象外。
未対応の結果呼び出し構文・型は未検証になる。通常の純粋式で結果が不明な場合は両経路を検査する。
呼び出しを含む短絡式や、完了操作とバッファ読み取りを同じ比較式へ置く構文は、
評価順序を勝手に決めず未検証にする。

ポーリングがいつか完了すること、最大周回数、実時間上限は証明しない。
既存の探索上限を超えた場合は未検証。
ブロック入口・出口契約、ヒープ由来、所有権統合、IRQ/コールバックへの移譲、
DMA 配置・アラインメント・キャッシュ等は引き続き別の未完了項目。

## 回帰検査

`python3 tests/run_tests_results.py` が実際の C、厳密JSON、CLI の終了コードと
結果分類・診断位置を検査する。`--kenbi PATH` で検査器を指定できる。
同じソースに逆の成功条件を適用するケース、失敗時の借用保持、戻り値の上書き、
別翻訳単位のヘルパー、ポーリング、型変換、未知仕様を含む。
フィクスチャと契約は独自作成の架空 API。外部コード・仕様の転載や依存追加はない。


## int 引数による結果の伝播（実装済み）

`source-scalar-arguments.c.v1` は、解析できる直接呼び出しで int 引数の zero/nonzero を
呼び出し先へ渡す。例えば `int rc = try_start(&t, b); recover(&t, rc);` に対し、
recover 内の `if (rc == 0) abort_transfer(t);` を実際の開始結果と対応付ける。
入れ子のヘルパー、値を返すヘルパー、別翻訳単位でもこの対応を保持する。

値渡し引数には、その呼び出し固有の記憶領域を作る。
callee が引数を代入やポインタ経由で変更しても、caller の元変数は変わらない。
引数のアドレスを外部APIに渡す場合も、既存 accesses 契約でその引数領域を検査し、
変更された値の情報を無効化する。int 型であるだけで成功値と判断することはない。
root の未知な入力値は不明のままで、実際に追跡できる値だけを伝播する。

int 引数そのものを非同期アクセスのバッファとして渡すことも、既存の借用規律で検査する。
関数復帰時には引数領域の寿命が終了するため、借用が残っていれば BORROW_OUTLIVES_BUFFER。
引数は caller の変数とは別領域なので、caller 側の変数が生存していても借用先の寿命は延長されない。
引数を書き換える際の借用競合や、返却前に完了させる正常系も検査する。

この機能は int のゼロ性の伝播であり、一般の値域解析・未初期化検査ではない。
unsigned/char/bool など幅・符号の異なる引数への変換を同じ値として伝播せず、
既存の保守的な不明値処理または未対応構文の診断を維持する。
関数ポインタや callback、IRQ への非同期の引数移譲を実装する機能でもない。
テスト: `python3 tests/run_tests_arguments.py`。架空API・フィクスチャは独自作成で、依存追加はない。
