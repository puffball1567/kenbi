# 非同期借用バッファの容量要求

2026-09-19。`source-borrow-capacity.c.v1` を実装。
既存の protocol 操作の `borrow` に `minBytes` を指定できる。
無条件の借用と `outcomes` 内の借用の両方に適用する。

```json
{"borrow": {"argument": 2, "mode": "read", "minBytes": 16}}
```

`minBytes` は 1〜1000000000 の整数で、借用開始時に証明すべき最低ストレージ容量。
省略時は従来の容量要求なし。指定値をバッファの実容量として仮定しない。
未知キー・不正型・範囲外は設定エラー（終了コード2）。デバイス固有の注釈は追加しない。
同じ C ソースに異なる仕様を適用し、必要容量に応じて受け入れ結果が変わる。

Clang の `clang_Type_getSizeOf` が返す、実際のコンパイル条件での固定長の自動変数・配列の
サイズを使用する。単位 `c-sizeof-bytes` は C の sizeof の単位であり、ホストのポインタ幅や
固定の int サイズを仮定しない。int 値引数自身を借用する場合は、その引数の記憶領域サイズを使う。

配列先頭・変数のアドレス、単純なポインタ別名、可視関数へのポインタ引数、別翻訳単位の
呼び出しまで容量を引き継ぐ。借用の起点を追跡する既存解析と別に、ポインタ式ごとの容量を保持する。
部分領域を同じ借用起点にまとめても、先頭からの容量を内部ポインタへ転用しない。
`b + n`、`b - n`、`&b[n]` の n が整数リテラル（括弧・単項 +/- を含む）の場合、
Clang の要素サイズに基づいて位置と残り容量を計算する。変数や一般の定数式は容量不明。
未知の入力ポインタ、型の配列引数表記、外部契約の宣言だけでは容量の事実を作らない。
ヒープ・可変長配列・静的ストレージ・型変換などは既存の解析未対応理由を維持する。

- 容量が必要値以上: 容量要求は検証済み。デバイス動作等の外部前提は引き続き conditional。
- 容量が必要値未満: `BORROW_CAPACITY_REQUIREMENT`、違反（終了コード1）。
- ポインタ演算がストレージ範囲外へ出る: `BORROW_POINTER_RANGE`、違反（終了コード1）。
- 容量が確定しない: `UNKNOWN_BORROW_CAPACITY`、未検証（終了コード1）。

各 obligation の `borrowCapacity` に、検査した要求・容量・状態・単位・仕様ファイル・
引数番号・ソース位置・呼び出し経路・結果分岐を記録する。確定時は `storageBytes` と
`byteOffset` も記録する。容量不明や範囲外は `availableBytes: null`。
末尾の一つ先は確定した残り容量ゼロとして、`availableBytes: 0` を記録する。
該当診断の `capacityRequirement` にも同じ証拠を含める。
配列容量の検証は外部APIが契約どおりに動作することの証明とは区別する。
成功時にだけ借用する場合は成功側の要求を検査し、失敗側の状態・借用は既存の結果依存モデルに従う。

これは転送サイズ引数の値域や全アクセスの範囲を証明するものではない。
型の保証配置によるアラインメント検証は末尾の追加節を参照。
DMA可能領域、MMIO、キャッシュ整合性、ヒープ所有権やプール容量の検証は引き続き未実装。
テストは `tests/run_tests_capacity.py` と独自作成の `tests/c/t250_borrow_capacity.c`。
依存追加・外部コードやデバイス仕様の取り込みはない。

## 定数オフセットの追跡（2026-09-19）

借用起点とは別に、ストレージサイズ・現在位置・既知/未知・範囲外の情報を保持する。
`short *` 等のオフセットは1要素を1バイトとせず、実際の型サイズで換算する。
別名・可視関数引数・別翻訳単位でも位置を保持し、内部ポインタから先頭へ戻す操作も検査する。
各演算を順番に確認し、最終的に範囲内へ戻っても途中で範囲外に出たポインタは違反を維持する。
末尾の一つ先の形成は許容するが、正の minBytes は満たさない。そこから範囲内に戻ることは可能。

整数の符号と幅を確認し、解析器の64bit符号付き整数へ収まらない値や要素サイズとの積が
収まらない値は未検証にする。範囲確認は加算前に行い、解析器自身の加算オーバーフローを避ける。
未知のオフセットを後の定数演算で既知へ戻さない。変数の初期値だけで実行時の値を断定しない。

この検査は minBytes が指定された借用の容量要求の一部。minBytes のない操作や一般の
ポインタ演算・CPUアクセスすべてを検証する機能ではない。借用の競合判定は引き続き
ストレージ全体に対して保守的に行い、部分領域同士を独立として扱わない。
追加テストは `tests/run_tests_offsets.py` と `tests/c/t251_borrow_offsets.c`。
