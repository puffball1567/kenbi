# 設定による再帰禁止（実装済み）

`source-recursion.c.v1` は、ソースの直接呼び出しグラフに循環があることを
`recurse` 効果として記録する。project の profile で禁止できる。

```json
{
  "profiles": {
    "bounded": {"forbid": ["recurse", "heap_allocate"]}
  }
}
```

これは project JSON の抜粋。checks または `@verify(bounded)` で適用する。
実行文脈の contexts / forbid でも同じ効果を禁止できる。
既存の extends 合成は和集合のため、子設定から親の再帰禁止を解除できない。

## 検査範囲

可視本体の直接再帰、複数関数間の相互再帰、別翻訳単位を経由する再帰、
ルート自身は再帰しなくても呼び出し先に存在する再帰を検出する。
探索中の呼び出し経路へ戻る辺と、解析済みの関数へ再訪する辺を区別する。
同じヘルパーを2回呼ぶ処理や、二つのヘルパーが共通の関数を呼ぶだけの構造を再帰とは扱わない。

`FORBIDDEN_EFFECT` は循環を閉じる呼び出し位置とルートからの callChain を示し、
obligation の effects に recurse が入る。
ソースの呼び出しグラフの検査であり、実行可能性の精密な証明ではない。
終了条件がある再帰や、引数によって実際には再帰しない呼び出しも、
グラフに循環があれば再帰禁止に反するものとして保守的に拒否する。
末尾呼び出し最適化で機械語から再帰が消えることも仮定しない。

ブロックの禁止は、指定ブロックとその呼び出し先に適用する。
ブロック前にあるだけの再帰呼び出しは、そのブロックの再帰禁止違反にはしない。
状態・借用の protocolScope と禁止効果の範囲の違いは[ブロック検証](configured_protocol_blocks.md)を参照。

## 外部契約と未検証

外部APIの effects は recurse も列挙できる。effects の完全な一覧は、再帰や
呼び戻しによる再入も含む、このモデルの効果を表す外部前提。
`effects: []` は再帰も行わないという前提を含む。未知の外部実装が自動的に
非再帰と判明する意味ではなく、正常系でも conditional のまま。
外部契約がない場合は未検証。間接呼び出しも既存の未解決診断を維持する。

本体が利用可能なら契約だけでは効果を隠せない。
本体が再帰するのに effects へ recurse がない契約は CONTRACT_EFFECT_MISMATCH。
再帰禁止の文脈で実行可能と宣言した本体も、その文脈の禁止に適合するか検査する。

profile が recurse を禁止しない場合、検出した効果は報告するが、それだけで違反にはしない。
状態・借用解析の再帰未対応による未検証判定は従来どおりで、今回の効果解析によって免除されない。

## 資源上限との区別

この機能は再帰の禁止要求を検査するもので、再帰深度上限、スタック最大使用量、
ループ上限、終了性、処理量や実時間の上限を証明するものではない。
非再帰でも大きなスタックフレームや無限ループは存在できる。
これらの資源・時間モデルは別の残作業として扱う。

テストは `python3 tests/run_tests_recursion.py`。
C フィクスチャと外付け契約は独自作成で、依存や外部コード・仕様の追加はない。
