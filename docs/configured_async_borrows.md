# 状態機械に結び付く持続借用

`--safety` の外付け状態機械で、開始から完了操作まで持続する借用を検査できる。
能力 ID は `source-async-borrows.c.v1`。操作の戻りやヘルパー関数の return では借用を終了しない。
[状態遷移検証](configured_protocols.md)と同じ経路探索・結果分類・入力ハッシュを使用する。

この能力は、追跡可能な自動変数・固定長配列の寿命と、その記憶領域に対する借用競合を対象とする。
DMA の領域・アラインメント・キャッシュ・MMIO・割り込み配信や、メモリ安全性全体の証明ではない。

## 状態仕様

開始操作に `borrow`、完了操作に `releaseBorrow` を追加する。
どちらも汎用語彙であり、API 名や機器名には依存しない。

```json
{
  "symbol": "c:@F@transfer_start",
  "argument": 1,
  "from": ["ready"],
  "to": "busy",
  "borrow": {"argument": 2, "mode": "read"}
}
```

```json
{
  "symbol": "c:@F@transfer_finish",
  "argument": 1,
  "from": ["busy"],
  "to": "ready",
  "releaseBorrow": true
}
```

借用は状態機械とリソースの組に紐付く。別リソースの完了で終了したり、状態を `ready` に
変更しただけで消えたりしない。一つのリソースにつき同時に一つの借用を保持する。
借用中の再取得、借用のないリソースでの完了は違反。
同じ操作での取得と終了、取得操作のないモデルの終了指定、不正な引数番号・mode・未知キーは入力エラー。

| 借用側の mode | CPU 読み取り | CPU 書き込み・解放・再配置 | 別の借用 |
| --- | --- | --- | --- |
| `read` | 許可 | 禁止 | `read` の共有のみ許可 |
| `write` | 禁止 | 禁止 | 禁止 |

DMA 送信のような読み取り側を `read`、受信のような書き込み側を `write` と表現できる。
モードは仕様の明示的な外部前提であり、機器が実際にその方向にだけアクセスすることは証明しない。

キャンセル受付を `busy → cancelling`、停止確認を `cancelling → ready` と定義し、
`releaseBorrow` は停止確認にだけ付ける。受付で解除しない限り、確認前の CPU アクセスや寿命切れも検出する。
`int` の zero/nonzero に応じた状態・借用は[結果別契約](configured_protocol_results.md)で指定できる。
それ以外の非 void 状態操作や結果契約の欠落は未検証となる。

## 外部メモリアクセス契約

借用を含む状態機械を選択した検証では、外部操作には完全な `accesses` 契約が必要。
借用がまだ始まっていない箇所にも要求する。効果契約の `effects: []` や
状態保存の `preservesProtocols: true` だけではメモリアクセスがないとは見なさない。

```json
{
  "symbol": "c:@F@buffer_release",
  "effects": [],
  "assumption": "buffer.api",
  "preservesProtocols": true,
  "accesses": [{"argument": 1, "mode": "release"}]
}
```

`accesses` の mode は `read`, `write`, `release`, `relocate`。
引数が指す記憶領域への同期的なアクセスを表し、取得した借用による非同期アクセスとは区別する。
完全なアクセス集合に加え、記載のない追跡領域への隠れたアクセスや、将来使うための別名の保持がないことを
外部前提に含む。グローバル変数や別スレッド経由の隠れたアクセスを省略してよいという意味ではない。
`accesses: []` はそのような同期的アクセス・隠れた別名保持がないという明示的な前提。

状態操作にも `accesses` を指定する。その操作自身の抽象状態遷移・指定した借用の取得終了以外の
同期的なメモリアクセスを記述する。同期アクセスは操作入口の借用状態に対して確認する。
完了操作内の CPU アクセスを、完了後のアクセスとして先取りして許可することはない。
`accesses` 配列の順番を実行順序と解釈せず、全アクセスを入口状態で検査した後に無効化を反映する。
`release` / `relocate` の後は、それまでの同一記憶領域を指す別名によるアクセス・再借用を拒否する。
再配置の戻り値に新しい記憶領域を結び付ける解析はまだない。

既知の外部 `free` / `realloc` は解放・再配置、`memcpy` / `memmove` は書き込み・読み取り、
`memset` は書き込み、`memcmp` / `memchr` / `strlen` は読み取りとして扱う。
空のアクセス契約でも、この既知のアクセスによる借用競合を隠せない。
長さや null によるアクセス省略の証明は行わず、保守的に扱う。
解放対象がどの確保関数に由来するかは[確保契約](configured_allocation.md)の `releasedBy` で検査する。
可視ヘルパーは本体をたどってアクセスを検査する。アクセス契約も付いた可視実装については、
契約への適合検査が未実装のため `MEMORY_CONTRACT_BODY_UNVERIFIED` を残す。

## ソースの追跡

固定長配列、数値型ローカル変数、単純なポインタ初期化、引数を介する別名を追跡する。
配列要素・ポインタ経由・数値型ローカル変数への単純代入、式・引数・return・条件内の読み取りを検査する。
定数により短絡すると分かる `&&` / `||` の右辺は読み取りに含めない。
それ以外の分岐条件間の関係は証明しない。

`&buffer[i]`, `buffer + i` などの追跡可能な部分領域も、元の記憶領域全体に結び付ける。
現段階では別々の添字が非重複であることを証明せず、同一配列上の競合は保守的に拒否する。
添字の範囲、アクセス幅、バッファ容量、初期化済みデータ、アラインメントを証明する機能ではない。

スコープ終了・return 時に、借用中バッファの寿命切れと、借用を終了しないリソースの寿命切れを検査する。
呼び出し先が caller のバッファを借りる場合、借用は caller に戻っても維持される。
呼び出し先が自身のローカルバッファを借用させたまま戻る場合は、その時点で寿命違反。
複数リソースが読み取り借用を共有する場合、一つを終了しても残りは維持される。

ループの収束判定には状態だけでなく、借用と無効化された記憶領域も含める。
状態が同じでも借用が残っている周回を、借用のない周回と同一視しない。

## 診断と未対応範囲

- `BORROW_ACCESS_CONFLICT`: CPU アクセスまたは別の借用との競合。
- `BORROW_OUTLIVES_BUFFER`: 完了前にバッファの寿命が終了。
- `BORROW_NOT_ENDED`: 借用終了前にリソースの寿命が終了。
- `BORROW_ALREADY_ACTIVE` / `BORROW_NOT_ACTIVE`: 二重取得・取得のない終了。
- `EXPIRED_BORROW_ORIGIN`: 寿命終了・解放・再配置済みの記憶領域を再使用。
- `MISSING_MEMORY_CONTRACT`, `UNKNOWN_BORROW_ORIGIN` 等: 必要な契約・由来を確立できず未検証。

可視ヘルパーの入口・出口要求は[関数境界契約](configured_function_boundaries.md)で検査できる。
ヒープ確保の戻り値からの由来追跡、呼び出し元情報なしの入力バッファ契約、グローバルや static の寿命契約、
所有権解析との統合、独立に呼ばれる割り込み・コールバックへの契約移譲は未実装。
通常の直接呼び出しとして完了ヘルパーをたどることはできるが、実際の割り込み配信の証明ではない。
ポインタ再代入、複合代入、キャスト、フィールドを経由する複雑な別名、volatile・atomic は未検証となる。
状態機械のブロック入出力、その他の未対応構文は[状態遷移検証](configured_protocols.md)と同じ。

借用に関する競合・寿命診断の `borrow` には、記憶領域とリソースの由来、モード、状態機械 ID、
開始位置 `acquiredAt` と開始時の呼び出し経路 `acquisitionCallChain` が付く。
違反時の呼び出し経路とは別に、どこで始まった借用が保護しているかを確認できる。

外部契約を受け入れた正常系は `conditional` となる。契約を書いたことだけで `verified` に昇格しない。
テスト: `python3 tests/run_tests_borrows.py`。モデルと C フィクスチャは独自の架空 API であり、
ベンダー仕様・ドライバ・OSS コーパスの転載や新しいパッケージ依存はない。


## 同一コードで送信・受信仕様を切り替える

両方の設定が同じ [C ソース](../demo/safety/async_driver.c) を使用する。

```sh
# read 借用: 転送中の CPU 読み取りが可能。両関数 conditional、終了コード 0
kenbi --format=json --safety=demo/safety/async-transmit.project.json

# write 借用: 転送中の CPU 読み取りは競合。全体 violation、終了コード 1
kenbi --format=json --safety=demo/safety/async-receive.project.json
```

完了後にアクセスする `completed` はどちらでも成立する。
この例は架空 API の借用モデルであり、実機 DMA ドライバの配置・キャッシュ・割り込みまでを検証したものではない。
