# 外付け契約と適用先ファイルの内容照合

2026-09-20。`source-contract-artifacts.v1` を実装。
contracts / protocols パッケージのルートに、任意の `artifacts` 配列を指定できる。
各要素には次の3フィールドを必須とする。

| フィールド | 内容 |
| --- | --- |
| path | 対象ファイル。相対パスは契約パッケージの所在ディレクトリを基準に解決 |
| sha1 | 要求するファイル内容のSHA-1。40桁の16進文字列。大文字・小文字を受理し出力は大文字 |
| role | `parsed-input` または `external-artifact` |

`parsed-input` はソース・ヘッダー等、Clangで実際に解析した入力に対象パスが含まれることも要求する。
ファイルが存在しハッシュが合っているだけでは満たさない。条件付きincludeで読み込まれなかった
ヘッダーや、無関係なファイルを指定して成功することを防ぐ。
パスは絶対化・字句的正規化して照合し、別名のシンボリックリンクを同じパスとは推定しない。

`external-artifact` はライブラリ・ボード仕様資料等のファイル内容を照合する。
そのファイルが実際にリンクされたことや、契約どおりに動作することは証明しない。
この区別はJSONにも残し、外部APIに依存する結果は引き続き明示前提付きの conditional とする。

指定時の配列は非空。未知キー・不正型・不正ハッシュ・未知role・同一パッケージ内の
重複パスは設定エラー。複数パッケージが同じファイルの同じハッシュを要求することは可能だが、
異なる要求は競合として拒否する。プロジェクトのextendsでも要求は引き継ぐ。
パッケージに含まれるすべての指定を確認し、未使用APIだからという理由で省略しない。
省略した従来パッケージには新しい対応確認の保証を付けない。

不一致・ファイル欠落・未解析の必須入力は `SAFETY_INPUT_ERROR`、status=unverified、
accepted=false、終了コード2とする。APIの動作違反とは区別した適用条件の不成立である。
正しい内容に差し替えた後は次回実行時に再確認する。過去の結果キャッシュは使用しない。

JSONの `contractArtifacts` にパス・role・パッケージID・宣言バージョン・契約ファイル・
requiredSha1・observedSha1・parsedを記録する。照合対象は `inputs` にも追加して、
既存の解析入力スナップショット照合の対象とする。読み込み中に同じパスの異なる内容を
観測した場合は上書きして成功させず、入力変更として拒否する。

SHA-1は既存入力記録と同じ変更検出用の形式。悪意ある改ざんに対する認証・署名検証や
配布元の真正性の保証ではない。バージョン文字列は引き続き宣言値であり、指定ファイル群が
ライブラリの全構成物を網羅すること、ビルド条件・ターゲットやリンク実体の一致は別の継続課題。

独自作成の `tests/c/t255_contract_artifacts.c` と `tests/run_tests_artifacts.py` で確認。
バイナリ役のファイルもテスト内で独自生成し、外部ライブラリやデバイス資料は取り込んでいない。
新しい依存はない。
