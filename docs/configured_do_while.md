# do-while の状態・借用・直接アクセス検証

順序付き解析で `do { ... } while (condition);` を扱う。
状態機械、借用、外部APIの容量/整列、profile.memoryAccessと併用する。
capabilityは `source-do-while.c.v1`。新規注釈や機種固有の契約は不要。

本体を必ず一度実行してから条件を評価する。continueは条件へ進み、break/returnは
条件式内の操作を実行せず退出する。条件式の直接呼び出しには既存のint結果
zero/nonzero対応付けを使用し、完了まで借用が続くポーリングも検査できる。

入口/出口の資源状態、バッファ起源・寿命、ポインタ再代入を経路ごとに保持し、
既存の固定点探索と予算を使う。二重開始、条件に到達する前の寿命切れ、完了前の
CPUアクセス、break/return時の未解放借用、範囲外アクセスを検出する。
可視ヘルパー・別翻訳単位・ブロック指定でも同じモデルを使う。

効果の要約は引き続き保守的で、break等で実行しない条件式の外部前提も報告に残る場合がある。
終了性・反復回数・実時間・割り込みによる進捗を証明する機能ではない。
無限反復の固定点で偽の復帰経路を作らず、解析予算超過は未検証にする。
一般のカウンタ算術や未対応式の条件は未検証を維持する。

回帰: `python3 tests/run_tests_do_while.py`。
`tests/c/t263_do_while.c` とC/JSON追加例は独自作成。外部コード・仕様・依存追加なし。
