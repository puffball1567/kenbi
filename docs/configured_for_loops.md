# for文の順序付き検証

`source-for-loops.c.v1` はCのfor文を状態・借用・メモリアクセス解析へ接続する。
初期化を一度実行し、条件、本体、更新式の順に探索する。continueは更新式へ進み、
break/returnは更新式を実行しない。条件省略は真として扱う。

Clangの子ノード数だけで省略された式を推測せず、ソース中のヘッダ区切りと
各子ノードの範囲を照合する。初期化・条件・更新式の任意の省略に対応し、
対応が曖昧なマクロや未対応のヘッダは未検証とする。

初期化宣言の変数はループ終了まで生存し、退出時に寿命を終える。
外側のポインタへの更新は維持し、ループ内の領域を指す参照が外へ残る場合は
後続アクセスを寿命切れとして拒否する。本体がcompound statementなら、
その局所領域は更新式より先に寿命を終える。

直接呼び出し・単純代入・既存の条件式を使用できる。条件APIのzero/nonzero結果、
更新式内のAPI、ヘルパー/別翻訳単位、ブロック指定、入れ子にも既存解析を適用する。
既存whileの固定点探索と解析予算を再利用する。

[ローカルの符号なし整数の独立した++/--](configured_unsigned_updates.md)に対応する。
符号なしの+=/-=にも上記の対応範囲で対応する。
符号付き整数は、下記の条件で上限が保証されるfor文の更新式に限って対応する。
それ以外の符号付き更新、一般のカウンタ算術、その他の複合代入、マクロ展開されたfor文は未対応。
未対応の式を実行する経路は未検証になり、回数上限・終了性・WCETを保証しない。
外部前提は引き続き条件付き判定として記録する。

回帰: `python3 tests/run_tests_for_loops.py`。
入力 `tests/c/t264_for_loops.c` と追加C/JSONは独自作成。
外部コード・仕様・依存追加なし。

## 条件で上限が保証される符号付きカウンタ（2026-09-25）

`source-signed-for-counters.c.v1`。for文の更新式にある符号付き整数の `i++` / `++i` / `i--` / `--i` を、
オーバーフローしないことをループ条件から導ける場合に限って受理する。

- 増加は条件 `i < E` または `E > i`、減少は条件 `i > E` または `E < i` の場合のみ。
  比較が i 自身の型で行われる（E がより広い型・符号なし型へ変換しない）こと。
  このとき、更新の直前に評価された条件から i は型の最大値未満（減少では最小値より大）となる。
- i は int / long / long long（汎整数拡張を受けない型）。short・char・volatile・_Atomic は対象外。
- i はその関数の自動変数または引数。static・グローバルは対象外。
- 関数内のどこでも i のアドレスを取らない。条件式と本体では i を読むだけで、
  代入・増減は条件式と本体の外（初期化部やループの前後）に限る。
  このため条件の評価から更新までの間に i が変わらない。
- 対象は C の翻訳単位のみ。

`i <= E`、`i != E`、条件なし、逆方向の更新、別の変数の更新、本体での i の変更、
アドレス取得、括弧で囲んだ更新対象 `(i)++`、マクロ経由の更新は従来どおり未対応（未検証）。
更新後の値は追跡せず、反復回数・終了性・WCET を導出しない。更新自体は i の記憶領域への
read / write として既存のメモリアクセス・借用競合の検査を受ける。

回帰: `tests/c/t297_signed_for_counters.c` と `tests/run_tests_signed_counters.py`（39件）。
独自作成の入力のみ。外部コード・仕様・依存の追加はない。
