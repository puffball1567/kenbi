# 借用・外部アクセスと読み取り専用ストレージ

2026-09-20。`source-storage-permissions.c.v1` を実装。
protocol検証で追跡する自動ストレージに、C型に基づく書き込み可否を保持する。
新しい注釈・自己申告設定は追加せず、Clangの型情報を既存の借用/アクセス契約と照合する。

- `const` のスカラー・配列・typedef経由のconst・多次元配列: 読み取り専用。
- 可変ストレージ: 書き込み可能。
- constメンバを含む構造体など、ストレージの一部分だけが読み取り専用: 書き込み可否は未検証。

借用元のoriginに可否を結び付け、ポインタ別名・定数オフセット・可視関数・別翻訳単位でも維持する。
`const char *` という見かけの型だけで、元の可変バッファを読み取り専用へ変更しない。
同様に `char * const` はポインタ変数自身のconstであり、指す先を読み取り専用へ変更しない。
int値引数は呼び出し先自身の記憶領域と型を使用する。const値をコピーして渡したという理由で、
可変の値引数をconstとして扱わない。

`borrow.mode: "write"`、外部APIの `accesses.mode: "write"`、追跡対象のCPU書き込みを照合する。
読み取り専用への書き込みは `READONLY_STORAGE_WRITE`（違反）。部分的なconst等で判断できない
書き込みは `UNKNOWN_STORAGE_PERMISSION`（未検証）。いずれも終了コード1で受け入れを拒否する。
read借用・readアクセスは読み取り専用ストレージにも可能で、既存の競合/寿命検査は維持する。

Cの宣言時初期化は後からの変更と区別する。初期値を代入する内部ノードだけに初期化の印を付け、
const intの正しい初期化を違反にしない。初期化式内で呼ぶ外部APIへの書き込み制約は免除しない。

protocolの抽象状態遷移だけから、ハンドルのC記憶領域が実際に書き換わるとは推定しない。
constハンドルを使うデバイス操作等でも、API契約がC記憶領域へのwriteを指定すれば照合する。
解放・再配置の合法性全体をconstだけで判断する機能ではなく、既存の借用/lifetime制約に従う。

診断のmemoryPermissionにorigin、storagePermission、accessを記録する。
未知の起点・未対応キャスト・未対応の構文は従来の未検証理由を維持する。
全メモリアクセスの網羅、ヒープ/所有権統合、文字列リテラル、グローバルストレージ、
部分領域の独立性、ターゲット設定のRAM/MMIO領域権限を保証するものではない。
外部APIが契約どおりに振る舞うことは引き続き明示的な前提として扱う。

独自作成の tests/c/t258_storage_permissions.c と tests/run_tests_permissions.py を使用。
既存libclangとNim標準ライブラリを使用し、外部コード・仕様・依存の追加はない。
